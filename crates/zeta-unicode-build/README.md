# zeta-unicode-build

> [!WARNING]
> **AI slop — loosely verified.** This crate (the encoder, build script, data handling and this
> README) was written almost entirely by an AI and reviewed only lightly by a human. The
> generated table *is* checked at build time against the vendored UCD files, and the crate's
> tests round-trip every name, but treat the rest — the design notes, the performance claims and
> the size figures below — as unverified marketing until you have measured them yourself. Read
> the code before you trust it.

## What it does

Turns the UCD text files into one compact Nomina image and a reproducible manifest. It
validates the inputs, builds the name corpus, encodes character names, emoji names, general
categories and patterns, tries several name-block sizes, verifies every section and records
what it consumed. It is a build-dependency of `zeta-unicode` and provides the
`zeta-unicode-train` CLI.

## Pipeline

```text
UCD files ──► validate ──► parse names + aliases
                              ├─ encode emoji / GC / patterns once
                              ├─ try name-block sizes
                              ├─ choose by budget and priority
                              └─ verify sections and layout
                                   │
                                   ├─► nomina.bin
                                   └─► manifest.json
```

Emoji, GC and patterns do not depend on the name layout, so they are built once. Only the name
section and final packing run per candidate. The same inputs and profile always produce
byte-identical output.

Inputs are `DerivedName.txt` (Unicode 10+), `DerivedGeneralCategory.txt`, `NameAliases.txt`,
`NamedSequences.txt` (optional before Unicode 4.1) and `emoji-test.txt`. Version headers must
agree with `DerivedName.txt`; the Emoji release is independent. The corpus is every explicit
name plus aliases for unnamed code points; Hangul and `*` patterns are generated by the runtime.

## Profiles and output

Defaults are `balanced`, shifts `[5, 6, 7, 8]` and a 200,000-byte budget. `size` picks the
smallest fitting image, `latency` the lowest fitting shift, and `balanced` the smallest image
at shift ≤6 or the smallest fallback. Ties go to the lower shift.

| Shift | Image | Preferred by |
|---:|---:|---|
| 5 | 199,258 | `latency` |
| 6 | 188,882 | `balanced` (default) |
| 7 | 183,658 | |
| 8 | 181,026 | `size` |

Output is `nomina.bin` plus `manifest.json`: versions, profile, candidates, section sizes,
input hashes and verification checks, with no timestamps or absolute paths. The build script
writes both to `OUT_DIR`; the CLI writes to `--out-dir`.

## Command line

```sh
cargo run -p zeta-unicode-build --bin zeta-unicode-train -- \
    --data-dir ../ucd/15.1.0 --out-dir target/nomina --report --verify
```

Options: `--data-dir`, `--out-dir`, `--block-shift` (3..=8), `--priority`, `--max-bytes`,
`--baseline`/`--max-delta`, `--report`, `--verify`.

## Verification and failure model

Every section round-trips through its decoder; the chosen names are re-decoded by an
independent build-time verifier and the image layout is re-parsed. The manifest checks are
`name-stream-round-trip`, `emoji-stream-round-trip`, `general-category-round-trip`,
`pattern-round-trip` and `image-layout`.

Bad inputs, profiles, budgets, baselines and I/O are errors. Malformed UCD records and
verification mismatches panic, so a returned `TrainOutput` is always verified.

```sh
cargo test -p zeta-unicode-build --all-features
```

See [`zeta-unicode`](../zeta-unicode/README.md) for the runtime and format, and
[`zeta-unicode-format`](../zeta-unicode-format/README.md) for the shared codec.
